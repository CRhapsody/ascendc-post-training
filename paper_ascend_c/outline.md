研究核心
利用强化学习提升 LLM 的 AscendC 算子生成能力，重点解决领域能力不足、长轨迹采样效率低以及训练信号稀疏的问题。

问题一：领域知识与 Agent 开发能力不足

现有通用 LLM 缺乏 AscendC 相关的领域知识以及专业算子开发经验，难以完成包含代码编写、编译调试和性能优化的复杂开发流程。同时，模型初始成功率较低，使得直接开展强化学习难以获得足够的有效探索轨迹。

解决方案：Harness-Augmented Agent Training

首先构建包含 AscendC 专业知识（Skills）和开发工具的 Agent Harness，为模型提供必要的领域知识和执行能力。然后，利用 Harness 批量构建包含完整算子开发过程的轨迹数据，通过 SFT 提升模型的领域知识运用和工具调用能力。最后，在相同的 Harness 环境中开展 RL，利用真实执行反馈进一步提升算子的正确性与运行性能。

问题二：长轨迹 Agent RL 的 Rollout 效率低

AscendC 算子开发需要多轮代码生成、编译、测试及优化，产生长度较长且差异显著的交互轨迹。这类工作负载使现有 RL 推理基础设施面临两个问题：

（1）Cache Locality： 同一轨迹的连续请求被分配到不同推理引擎时，历史 KV Cache 难以复用，增加重复 Prefill 开销。

（2）Load Imbalance： 不同轨迹的执行时间、上下文长度和工具调用次数存在较大差异，导致引擎负载不均，且固定 Session 绑定可能进一步加剧负载倾斜。

解决方案：Trajectory-Aware Rollout Optimization

基于 Polar + Slime 强化学习框架，优化多轮 Agent 的 Rollout 调度机制。通过 Session-Aware Routing 增强 KV Cache 局部性，并引入负载均衡策略缓解不同推理引擎之间的工作负载差异，从而提升长轨迹 Rollout 的执行效率。

问题三：任务难度高导致 RL 训练信号稀疏

AscendC 算子生成涉及代码结构、编译、功能正确性及性能优化等多个阶段。由于任务难度较高，大量轨迹无法完成最终目标，导致终局奖励稀疏。在 GRPO 训练中，这进一步表现为大量轨迹组奖励相同、组内优势为零，有效训练组数量不足。

解决方案：Sparse-Feedback RL Optimization

首先设计多阶段可验证奖励，对不同开发阶段的完成情况提供更细粒度的反馈，提高奖励区分度。然后引入动态采样，过滤缺乏有效优势信号的轨迹组，减少无效参数更新。最后引入动态过采样机制，补充有效训练组，维持训练批次规模，提高有限训练预算下的有效数据供给。
